# underhood badge spec

Version 0.1

The underhood badge is a two-item checklist that describes how a project behaves **when the shipped program runs**.

| item | meaning |
|------|---------|
| ⚙ mech | Deterministic code: written rules, same input → same output (Software 1.0). |
| ✨ magic | Inference: output produced by a trained model (Software 2.0 or 3.0). |

## Marks

Each mark means the same thing on both items:

| mark | meaning |
|------|---------|
| ✓ | Required. The project's main function needs it. |
| ~ | Optional. The project uses it, but its main function still works without it. |
| ✗ | Absent. |

## Levels

Something has to be able to run, so if one item is absent, the other must be required. That leaves six valid levels. The first five run from pure code to pure model; `either` is for projects that can run as either one alone.

| level | mech | magic | definition | file |
|-------|-----|-----|------------|------|
| `code-only` | ✓ | ✗ | No model is called at runtime. | `badges/code-only.svg` |
| `model-optional` | ✓ | ~ | All core features work with every model disabled or unreachable. A model adds extra features. | `badges/model-optional.svg` |
| `fully-loaded` | ✓ | ✓ | The main function needs both the project's own logic and a model. | `badges/fully-loaded.svg` |
| `code-optional` | ~ | ✓ | The model does the work. Scripts or tools help it, but the model can do the job without them. | `badges/code-optional.svg` |
| `model-only` | ✗ | ✓ | No code at all. The project is only prompts, skills or instructions for a model. Rare today. | `badges/model-only.svg` |
| `either` | ~ | ~ | Either one alone can do the job: the project runs as pure code or as pure inference, for example a rules-based mode and a model mode. | `badges/either.svg` |

The other three combinations (✗✗, ~✗, ✗~) leave nothing that can run on its own. A project with no code and no model (a docs repo, for example) leaves the badge off.

## What checks the mech

Any code in the project counts, even a small loader script. ✗ means there is no code at all. Use ~ when the project still works without its code and ✓ when it doesn't.

## What counts as inference

Counts:

- Calling a hosted model API (LLM, embedding, vision, speech).
- Running local weights (llama.cpp, ONNX, transformers, a bundled classifier).
- Embedding-based search or ranking, even when decoding is deterministic.
- Temperature-0 or seeded generation. The output still depends on weights the project's code does not define.

Does not count:

- Code written with an AI assistant. The badge describes runtime, not authorship.
- Models used only in development, tests or CI.
- Classic statistics or heuristics whose parameters are written in the source or fitted by the project's own code.

## Choosing between ✓ and ~

Remove the item and check whether the README's first usage example still works. For the magic: turn off every model. For the mech: delete the scripts and tools and let the model work alone. If the example still works, mark that item ~.

## Rendering

72 × 20 px, shields.io "flat" proportions, two 36 px segments on `#555d59`, white marks. All glyphs are paths, so no fonts are needed. Generated by `src/badge.js`.
